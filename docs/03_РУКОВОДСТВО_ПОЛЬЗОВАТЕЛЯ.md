# ExcelForge — руководство пользователя

## 1. О программе

**ExcelForge** — настольное приложение для автоматизации обработки таблиц Excel. Вы описываете последовательность действий в файле сценария (пайплайн, формат YAML), а программа выполняет их с помощью библиотеки **pandas**: загрузка, фильтрация, объединение, расчёты и сохранение результата.

Программа рассчитана на пользователей, которые регулярно готовят однотипные отчёты из выгрузок и хотят снизить долю ручной работы в Excel.

---

## 2. Основные понятия

| Термин | Значение |
|--------|----------|
| **Пайплайн** | Файл `.yaml` / `.yml` со списком шагов |
| **Шаг** | Одна операция (загрузка, фильтр, сохранение и т.д.) |
| **DataFrame (DF)** | Таблица в памяти; у каждой своё имя (`df_main`, `rita`, …) |
| **Контекст** | Набор всех DF, накопленных при выполнении пайплайна |
| **Протокол** | Журнал выполнения: сообщения, ошибки, предупреждения |

Имена DF задаются в параметрах шагов (`dataframe`, `source_df`, `target_df`).

---

## 3. Интерфейс

### 3.1. Runner (выполнение)

1. Укажите **каталог пайплайнов** (по умолчанию `pipelines` в папке программы).
2. Выберите файл в списке слева.
3. Нажмите **«Запустить»**.
4. Следите за **протоколом** справа; при ошибке выполнение останавливается (если шаг не обрабатывает ошибку отдельно).

Кнопка **«Отмена»** прерывает длительный запуск.

### 3.2. Builder (конструктор)

- **Новый / Открыть / Сохранить** — работа с YAML.
- Список шагов слева: добавление, удаление, перемещение вверх/вниз.
- Редактор параметров выбранного шага (YAML-поля `params`).
- **Документация шага** — справка по параметрам с форматированием.
- **Предпросмотр / выполнить до шага** — отладка: в памяти остаются DF после отработанных шагов.
- **Просмотр DataFrame** — таблица первых N строк (N задаётся в «Общих настройках»).

### 3.3. Общие настройки

- Число строк **предпросмотра** DF (1–5000).
- **Шрифт** интерфейса: семейство, размер, «Применить», «Сохранить».
- **Сбросить настройки** — возврат к значениям по умолчанию.

Настройки сохраняются в `%APPDATA%\ExcelForge\settings.json`.

## 4. Создание пайплайна с нуля

### Шаг 1. Новый пайплайн

Builder → **«Новый»** → задайте **описание** → **«Сохранить как…»**.

### Шаг 2. Загрузка данных

Добавьте шаг **«Загрузка Excel → DataFrame»** (`load_excel`):

- `input_mode: file` — один файл, или `mask` — все файлы по маске в папке.
- `dataframe` — имя таблицы в контексте, например `df_main`.

### Шаг 3. Обработка

Примеры:

- **Фильтрация строк** (`filtration`) — условия `contains`, `==`, длина строки и др.
- **Запросы** (`query`) — текстовый фильтр pandas `query` + строковые фильтры.
- **Merge** — объединение двух DF по ключам.
- **Операции с DF** — склейка колонок, ВПР (`map_lookup`), расчёт колонки.
- **Группировка** — сводные по группам.

### Шаг 4. Сохранение

Шаг **«Выгрузка DataFrame → Excel»** (`save_excel`):

- `out_dir`, `filename`
- без шаблона — простая запись;
- с `template_path` — запись в макет Excel.

### Шаг 5. Проверка

В Builder: выделите последний шаг → предпросмотр / выполнение до шага → **«Просмотр DataFrame»**.

Затем запустите весь пайплайн в **Runner**.

## 5. Справочник типов шагов (кратко)

| Тип (`type`) | Название в UI |
|--------------|----------------|
| `globals_settings` | Общие настройки и установки |
| `load_excel` | Загрузка Excel → DataFrame |
| `save_excel` | Выгрузка DataFrame → Excel |
| `cast_column_type` | Преобразование типа столбца |
| `text_transform` | Текстовые преобразования столбца |
| `filtration` | Фильтрация строк |
| `filter` | *(алиас filtration)* |
| `transpose_df` | Транспонировать DataFrame |
| `query` | Запросы к датафреймам |
| `drop_rows` | Удаление строк |
| `merge` | Merge (объединение датафреймов) |
| `concat_dfs` | Склеить датафреймы |
| `rename_columns` | Переименование столбцов |
| `groupby_aggregate` | Группировка (groupby) и агрегации |
| `sort_list_output` | Сортировка и вывод по списку |
| `df_assign` | Операции с DF (столбец, выбор, подстановка, пустые) |

Подробные параметры каждого шага — в **документации шага** в Builder или в файле `app/docs/pipeline_steps.md`.

## 6. Типовые сценарии

### 6.1. Один отчёт из одного файла

```yaml
steps:
  - type: load_excel
    params:
      input_mode: file
      file_path: "C:/data/in.xlsx"
      dataframe: df_main
  - type: filtration
    params:
      source_df: df_main
      target_df: df_main
      expression:
        op: and
        items:
          - { col: "Статус", cmp: "==", value: "OK" }
  - type: save_excel
    params:
      export_mode: single
      source_df: df_main
      out_dir: "C:/data/out"
      filename: "report.xlsx"
      template_path: ""
```

### 6.2. Несколько таблиц на листы одной книги

```yaml
  - type: save_excel
    params:
      export_mode: mask_sheets
      out_dir: "C:/out"
      filename: "all.xlsx"
      template_path: ""
      name_glob: "df_*"
      writer_mode: w
```

Все DF в контексте, чьи имена совпадают с маской `df_*`, попадут на отдельные листы (имя листа = имя DF).

### 6.3. Интерактивный выбор файла при запуске

В `load_excel` или `save_excel`:

```yaml
file_open_dialog: on
file_open_dialog_help: "Выберите файл выгрузки"
```

Диалог появляется только при запуске из GUI.

### 6.4. Глобальные пути (@переменные)

Шаг `globals_settings` задаёт переменные (каталоги, маски), которые подставляются в последующие шаги как `@имя_переменной` в строках YAML.

## 7. save_excel — режимы записи

| Режим | Параметры | Назначение |
|-------|-----------|------------|
| Один DF | `export_mode: single`, `source_df` | Классическая выгрузка |
| Несколько листов | `export_mode: mask_sheets`, `name_glob` / `dataframes` | Один xlsx, лист = имя DF |
| Шаблон | `template_path`, `template_write_mode` | Запись в макет |
| Разбиение | `split_by_column`, `split_filename_mask` | Много файлов по значениям колонки |
| Дописать в книгу | `writer_mode: a`, `if_sheet_exists` | replace / overlay / error / new |

## 8. Отладка и диагностика

1. **Протокол Runner** — первая точка поиска причины сбоя.
2. **Выполнить до шага** в Builder — изоляция проблемного шага.
3. **Просмотр DF** — проверка имён колонок и типов данных.
4. Ошибки «столбец не найден» — сверьте имена с заголовками Excel (пробелы, регистр).
5. При `dtype: str` в load_excel все поля текстовые; для сравнений `>` / `<` используйте `cast_column_type` или числовые шаги `df_assign` (`calc_column`).

## 9. Организация файлов на диске

Рекомендуемая схема:

```
C:/ExcelForgeWork/
  pipelines/          # сценарии YAML
  input/              # входные выгрузки
  templates/          # шаблоны xlsx
  output/             # результаты
  archive/            # архив прошлых периодов
```

В YAML используйте полные пути или переменные `globals_settings`.

---

## 10. Безопасность и ограничения

- Пайплайн выполняется **локально**; данные не отправляются на сервер.
- Не храните пароли в YAML; пути к сетевым папкам — с учётом прав доступа Windows.
- Очень большие файлы (сотни тысяч строк) требуют достаточной RAM.
- Сложная логика, не покрытая шагами, может потребовать доработки программы (новый тип шага).
