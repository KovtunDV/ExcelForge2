# ExcelForge — руководство пользователя

## 1. О программе

**ExcelForge** — настольное приложение с интерфейсом **PySide6 (Qt 6)** для автоматизации обработки таблиц Excel. Вы описываете последовательность действий в файле сценария (пайплайн, формат YAML), а программа выполняет их с помощью **pandas**: загрузка, фильтрация, объединение, расчёты и сохранение результата.

Программа рассчитана на пользователей, которые регулярно готовят однотипные отчёты из выгрузок и хотят снизить долю ручной работы в Excel.

**Запуск:** `python -m app.main` или `run-excelforge.bat` (Windows).

---

## 2. Основные понятия

| Термин | Значение |
|--------|----------|
| **Пайплайн** | Файл `.yaml` / `.yml` со списком шагов |
| **Шаг** | Одна операция (загрузка, фильтр, сохранение и т.д.) |
| **DataFrame (DF)** | Таблица в памяти; у каждой своё имя (`df_main`, `glob_raw`, …) |
| **Локальный контекст** | DF текущего запуска пайплайна; после нового запуска не сохраняется |
| **Глобальный контекст** | DF с именем `glob_*` — живут в сеансе приложения между пайплайнами |
| **Протокол** | Журнал выполнения: сообщения, ошибки, предупреждения |

Имена DF задаются в параметрах шагов (`dataframe`, `source_df`, `target_df`).

## 3. Интерфейс

Главное окно — три вкладки: **Runner**, **Builder**, **Общие настройки**. Размеры панелей можно менять перетаскиванием разделителей (splitter).

### 3.1. Runner (выполнение)

**Верхняя строка:** каталог пайплайнов, кнопки **«Выбрать…»** и **«Обновить список»**.

**Левая колонка:**

- Список файлов `*.yaml` / `*.yml` (ширина рассчитана на длинные имена).
- **«Запустить»** / **«Отмена»** — полный прогон выбранного сценария; отмена прерывает фоновый поток.
- Индикатор прогресса.

**Правая колонка** (вертикально 50/50):

| Блок | Содержание |
|------|------------|
| **Информация** | Имя, описание и метаданные выбранного YAML |
| **Протокол** | Журнал выполнения; занимает доступную высоту панели |

При выборе пайплайна в блоке «Информация» отображаются поля из YAML (`name`, `description` и т.д.). Во время и после запуска смотрите **протокол** — там же сообщения об обновлении `glob_*`.

**Типовой порядок работы:**

1. Укажите каталог (по умолчанию `pipelines` в папке программы).
2. Выберите файл в списке.
3. Нажмите **«Запустить»**.
4. При ошибке выполнение останавливается (если шаг не обрабатывает сбой отдельно).

Диалоги выбора файла/папки из YAML (`params.dialogs` или inline `@file_open_dialog(…)`) показываются **только при запуске из GUI**.

### 3.2. Builder (конструктор)

**Верх:** путь к файлу, описание пайплайна, кнопки **Новый / Открыть / Сохранить / Сохранить как…**.

**Центр (горизонтальный разделитель):**

| Слева | Справа |
|-------|--------|
| Список шагов, добавление по типу, удаление, вверх/вниз, клонирование | Редактор выбранного шага |

**Правая панель — редактор шага:**

- **ID** и **Type** на одной строке (поля ~25 символов шириной); Type только для чтения.
- **Комментарий** — попадает в YAML как `comment`.
- **Params (YAML)** — основной редактор параметров; высокая область ввода, не перекрывается кнопками ниже.
- **Управление параметрами:** «Применить в шаг», «Сбросить к default», **«Документация по шагу»**; для шагов с путями — кнопки выбора файла/каталога/шаблона.
- **Тестовый запуск:** «Запустить пайплайн», **«Просмотр данных»**, «Выполнить до текущего шага», «Проверить шаг», «Отмена».

**Внизу окна:** блок **«Протокол»** фиксированной высоты (~5 строк текста) — удобен при отладке, не забирает место у редактора параметров.

**Документация по шагу** открывается в **отдельном немодальном окне** (Markdown → HTML в `QTextBrowser`). Окно можно оставить открытым и продолжать править YAML в Builder.

**Отладка:**

| Действие | Эффект |
|----------|--------|
| Выполнить до текущего шага | В памяти остаются DF после отработанных шагов (`_debug_ctx`) |
| Просмотр данных | Таблица из локального контекста отладки **или** из глобального `glob_*` (см. §3.3) |
| Проверить шаг | Выполняется только выделенный шаг |

Перед закрытием Builder с несохранёнными изменениями программа запросит сохранение.

### 3.3. Глобальные датафреймы (`glob_*`)

Если в параметрах шага указать имя DF с префиксом **`glob_`** (например `glob_raw`, `glob_prepared`), таблица сохраняется в **глобальном контексте сеанса** и доступна из любого пайплайна при следующих запусках. Обычные имена (`df_main`, `rita`, …) живут только в рамках одного запуска.

**Типичный сценарий:**

1. **Runner** — пайплайн A: долгая загрузка → `dataframe: glob_raw`.
2. **Builder** — пайплайн B: `source_df: glob_raw` без повторного `load_excel`.
3. **Просмотр данных** в Builder работает и после Runner-only: если отладочный контекст пуст, но есть `glob_*`, откроется предпросмотр с подписью «глобальный контекст сессии».

В протоколе при записи `glob_*` появляется строка вида `Global DF updated: …`.

**Управление:**

- Вкладка **«Общие настройки»** — список глобальных DF (имя, строки × столбцы), **«Обновить список»**, **«Очистить глобальный контекст»** (с подтверждением).
- Список обновляется при открытии вкладки; учитываются DF, созданные только в Runner.
- После очистки предпросмотр и новые запуски не видят старые `glob_*`.

### 3.4. Просмотр DataFrame

Окно открывается из Builder (**«Просмотр данных»**).

- Слева — список имён DF в текущем контексте (локальный + глобальный).
- Справа — таблица первых **N** строк (N — в «Общих настройках», 1–5000).
- **Фильтр** — подстрока по всем видимым ячейкам строки.
- **Сортировка** — щелчок по заголовку столбца (повтор — обратный порядок).

Окно можно оставить открытым и перезапускать шаги — список DF обновляется после выполнения.

### 3.5. Общие настройки

| Параметр | Описание |
|----------|----------|
| **Каталог пайплайнов** | Папка с YAML для Runner и Builder; **Обзор…** — выбор папки; **По умолчанию** — снова `pipelines` в каталоге запуска. **Применить** — сразу в Runner/Builder; **Сохранить** — запомнить между сеансами |
| Строк предпросмотра | Сколько строк DF показывать в окне просмотра |
| Шрифт / размер | Список семейств из системы (`QFontDatabase`); **Применить** — сразу в UI; **Сохранить** — в файл настроек |
| Глобальный контекст | Список `glob_*`, обновление и очистка |
| Сбросить настройки | Возврат к значениям по умолчанию |

Настройки хранятся в `%APPDATA%\ExcelForge\settings.json` (в том числе `pipelines_dir`). Шрифт применяется ко всему приложению, включая протокол.

## 4. Создание пайплайна с нуля

### Шаг 1. Новый пайплайн

Builder → **«Новый»** → задайте **описание** → **«Сохранить как…»**.

### Шаг 2. Загрузка данных

Добавьте шаг **«Загрузка Excel → DataFrame»** (`load_excel`):

- `input_mode: file` — один файл, или `mask` — все файлы по маске в папке.
- `dataframe` — имя таблицы в контексте, например `df_main` или `glob_raw` для сессионного хранения.

### Шаг 3. Обработка

Примеры:

- **Фильтрация строк** (`filtration`) — условия `contains`, `==`, длина строки и др.
- **Запросы** (`query`) — текстовый фильтр pandas `query` + строковые фильтры.
- **Merge** — объединение двух DF по ключам.
- **Операции с DF** — склейка колонок, ВПР (`map_lookup`), расчёт колонки.
- **Группировка** — сводные по группам.

### Шаг 4. Сохранение

Шаг **«Выгрузка DataFrame → Excel»** (`save_excel`):

- `out_dir`, `filename`
- без шаблона — простая запись;
- с `template_path` — запись в макет Excel.

### Шаг 5. Проверка

В Builder: выделите последний шаг → **«Выполнить до текущего шага»** → **«Просмотр данных»**.

Затем запустите весь пайплайн в **Runner**.

## 5. Справочник типов шагов (кратко)

| Тип (`type`) | Название в UI |
|--------------|----------------|
| `globals_settings` | Общие настройки и установки |
| `load_excel` | Загрузка Excel → DataFrame |
| `save_excel` | Выгрузка DataFrame → Excel |
| `cast_column_type` | Преобразование типа столбца |
| `text_transform` | Текстовые преобразования столбца |
| `filtration` | Фильтрация строк |
| `filter` | *(алиас filtration)* |
| `transpose_df` | Транспонировать DataFrame |
| `query` | Запросы к датафреймам |
| `drop_rows` | Удаление строк |
| `merge` | Merge (объединение датафреймов) |
| `concat_dfs` | Склеить датафреймы |
| `rename_columns` | Переименование столбцов |
| `groupby_aggregate` | Группировка (groupby) и агрегации |
| `sort_list_output` | Сортировка и вывод по списку |
| `df_assign` | Операции с DF (столбец, выбор, подстановка, пустые) |
| `file_ops` | Операции с файлами (копирование, перемещение, удаление, ZIP) |
| `group_template_export` | Групповой вывод по шаблону (Excel) |

Подробные параметры — в **«Документация по шагу»** в Builder или в [app/docs/pipeline_steps.md](../app/docs/pipeline_steps.md).

## 6. Типовые сценарии

### 6.1. Один отчёт из одного файла

```yaml
steps:
  - type: load_excel
    params:
      input_mode: file
      file_path: "C:/data/in.xlsx"
      dataframe: df_main
  - type: filtration
    params:
      source_df: df_main
      target_df: df_main
      expression:
        op: and
        items:
          - { col: "Статус", cmp: "==", value: "OK" }
  - type: save_excel
    params:
      export_mode: single
      source_df: df_main
      out_dir: "C:/data/out"
      filename: "report.xlsx"
      template_path: ""
```

### 6.2. Общая загрузка и несколько отчётов

```yaml
# Пайплайн load_globals.yaml
steps:
  - type: load_excel
    params:
      input_mode: mask
      directory: "C:/data/in"
      pattern: "*.xlsx"
      dataframe: glob_raw
```

```yaml
# Пайплайн report.yaml — без повторной загрузки
steps:
  - type: filtration
    params:
      source_df: glob_raw
      target_df: df_filtered
      expression: { ... }
  - type: save_excel
    params:
      export_mode: single
      source_df: df_filtered
      out_dir: "C:/data/out"
      filename: "report.xlsx"
```

Запустите сначала загрузку в Runner, затем отчёт в Builder или Runner.

### 6.3. Несколько таблиц на листы одной книги

```yaml
  - type: save_excel
    params:
      export_mode: mask_sheets
      out_dir: "C:/out"
      filename: "all.xlsx"
      template_path: ""
      name_glob: "df_*"
      writer_mode: w
```

Все DF в контексте, чьи имена совпадают с маской `df_*`, попадут на отдельные листы (имя листа = имя DF).

### 6.4. Интерактивный выбор файла при запуске

В `load_excel`, `save_excel`, `file_ops` и др.:

```yaml
dialogs:
  - kind: file_open
    title: "Выберите файл выгрузки"
    assign: file_path
  - kind: file_save
    title: "Сохранить результат как"
    assign_dir: out_dir
    assign_name: filename
    initial_file: result.xlsx
    default_extension: .xlsx
```

Или inline в параметре: `file_path: "@file_open_dialog(Выберите файл)"`.

Появится стандартный диалог Qt (только из GUI).

### 6.5. Глобальные пути (@переменные)

Шаг `globals_settings` задаёт переменные (каталоги, маски), которые подставляются в последующие шаги как `@имя_переменной` в строках YAML.

## 7. save_excel — режимы записи

| Режим | Параметры | Назначение |
|-------|-----------|------------|
| Один DF | `export_mode: single`, `source_df` | Классическая выгрузка |
| Несколько листов | `export_mode: mask_sheets`, `name_glob` / `dataframes` | Один xlsx, лист = имя DF |
| Шаблон | `template_path`, `template_write_mode` | Запись в макет |
| Разбиение | `split_by_column`, `split_filename_mask` | Много файлов по значениям колонки |
| Дописать в книгу | `writer_mode: a`, `if_sheet_exists` | replace / overlay / error / new |

## 8. Отладка и диагностика

1. **Протокол** — Runner (полная высота) или Builder (компактный блок внизу).
2. **Выполнить до текущего шага** — изоляция проблемного шага.
3. **Просмотр данных** — имена колонок, фильтр, сортировка; при только `glob_*` — глобальный контекст.
4. Ошибки «столбец не найден» — сверьте имена с заголовками Excel (пробелы, регистр).
5. При `dtype: str` в load_excel все поля текстовые; для сравнений `>` / `<` используйте `cast_column_type` или `df_assign` (`calc_column`).
6. После **очистки глобального контекста** перезапустите загрузку в `glob_*`, если пайплайн на них ссылается.

## 9. Организация файлов на диске

Рекомендуемая схема:

```
C:/ExcelForgeWork/
  pipelines/          # сценарии YAML
  input/              # входные выгрузки
  templates/          # шаблоны xlsx
  output/             # результаты
  archive/            # архив прошлых периодов
```

В YAML используйте полные пути или переменные `globals_settings`.

## 10. Безопасность и ограничения

- Пайплайн выполняется **локально**; данные не отправляются на сервер.
- Не храните пароли в YAML; пути к сетевым папкам — с учётом прав доступа Windows.
- Очень большие файлы (сотни тысяч строк) требуют достаточной RAM; `glob_*` держит копию в памяти до очистки или закрытия программы.
- Сложная логика, не покрытая шагами, может потребовать доработки программы (новый тип шага).
